# Release v1.101.2

## Summary

v1.101.2 completes the participant-decoupling stack (PR1–PR6), ships enhancer handoff-only completion with standard task-pipeline delivery, hardens native task delivery and agent stop convergence, and fixes Codex enhancer spawn teardown races. **100 files changed** (+1,755 / −897) across **57 commits** on `release/v1.101.2` vs `master`.

## Themes

### 1. Handoff and task delivery correctness

| PR    | Scope                                                                            |
| ----- | -------------------------------------------------------------------------------- |
| #1523 | Sender shows `agent.waiting` after handoff; queue promotion ordering fixed       |
| #1525 | Stale-turn detection local to daemon (slot + pending task, no participant reads) |
| #1533 | Native delivery unified on inbox reconcile path                                  |
| #1534 | Wake offline agents when queued messages promote                                 |

**Outcome:** Handoffs promote the queue before the target task, stale native turns reconcile locally, and promoted work wakes offline agents without participant presence hacks.

### 2. Participant decoupling (PR1–PR6)

| PR    | Scope                                                                     |
| ----- | ------------------------------------------------------------------------- |
| #1524 | Remove participant fields from task snapshot projection and wire contract |
| #1526 | Native activity via lifecycle outbox + backend heartbeat projection       |
| #1530 | Role status read model decoupled from `chatroom_participants`             |
| #1531 | Webapp presence/`lastSeenAt` from role status read model                  |
| #1532 | Operational `viewState` from projection only (no `lastStatus` inference)  |

**Outcome:** Snapshots, daemon delivery, UI presence, and operational status no longer read participant presence for hot paths. `chatroom_participants` remains the write path for orchestration, handoff routing, and session lifecycle — see [participant decoupling backlog](../migrations/participant-decoupling-stack.md#remaining-readers-complexity-order).

### 3. Enhancer handoff-only completion

| PR    | Scope                                                                                     |
| ----- | ----------------------------------------------------------------------------------------- |
| #1527 | Complete running enhancer job on `isEnhancerDelivery` handoff                             |
| #1528 | Remove `chatroom enhancer complete` CLI; spawn envelope uses handoff                      |
| #1529 | `getTaskDeliveryForJob` + thin `job-subscriber`; ephemeral release on terminal transition |
| #1539 | Codex: emit `agent_end` on intentional abort; wait before `service.stop()`                |

**Outcome:** Enhancer agents complete via `chatroom handoff` only. Remote daemon delivery uses the standard task pipeline (`getTaskDeliveryForJob` → `generateFullCliOutput`). Ephemeral enhancer roles release on terminal task transitions. Codex teardown no longer logs `spawn-error` when the job completes normally.

## Behavioral changes (user-visible)

- **Handoff:** Sender role transitions to waiting immediately after handoff; no stuck "working" on entry point after delegating.
- **Enhancer:** No `chatroom enhancer complete` command; enhancer returns via handoff. UI clears enhancer WORKING after handoff (ephemeral release).
- **Agent panel:** Presence dots and `lastSeenAt` sourced from role status read model, not participant timeline.
- **Queue promotion:** Offline agents wake when their queue slot promotes.
- **Codex enhancer:** Clean job completion without spurious abort/spawn-error in logs.

## Test coverage highlights

- Handoff sender waiting status (`messages.spec.ts`)
- Stale native handoff recovery and lifecycle outbox heartbeats
- Enhancer normal handoff, spawn/delivery output (no `enhancer complete`)
- `getAgentViewStatus` projection-only inference
- Agent stop TTL and orphaned command convergence
- Codex intentional abort → `agent_end` (job-subscriber grace window)
